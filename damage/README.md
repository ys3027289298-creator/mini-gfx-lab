# damage

分阶段伤害管线：暴击、护甲、抗性、减伤按固定顺序结算，每阶段可单独关闭；
逐阶段 trace 可对账手算；可枚举阶段顺序并量化差异；所有数值越界饱和而非溢出。

```bash
make test
```

## 固定阶段

```text
base → 暴击 → 护甲 → 抗性 → 减伤 → final
```

| 阶段 | 公式（整数、千分比） | 参数范围 |
|---|---|---|
| 暴击 | `roll < chance ? dmg * mult / 1000 : dmg` | chance 0..10000 bp；mult 100..10000‰ |
| 护甲 | `max(0, dmg - armor)` | 0..`DMG_MAX` |
| 抗性 | `dmg * (1000 - resist) / 1000` | -900..900‰（负值=易伤） |
| 减伤 | `dmg * (1000 - reduction) / 1000` | 0..900‰ |

每个乘除阶段向下取整，因此 trace 中的每一步都能精确手算复核。
暴击目标是确定性输入（`crit_roll_bp`），同一配置与输入必然得到同一结果。

## 单一配置入口

所有属性只通过 `DmgConfig` 传入，`dmg_config_sanitize()` 在入口一次性夹取范围；
各阶段不再各自解释属性，改抗性只需要改一处。每阶段的 `enabled[]` 独立控制开关，
关闭的阶段在 trace 中标记 `skipped`，数值原样传递。

`dmg_resolve()` 只走固定顺序（生产路径）。`dmg_resolve_order()` 仅用于分析，
传入非 4 阶段排列会返回 `-1`。

## 顺序差异量化

- `dmg_diff(a, b, &diff)`：最终伤害差、相对千分比、按阶段的最大偏差。
- `dmg_order_sweep()`：枚举全部 4! = 24 种顺序，给出 `min_final` / `max_final` / `spread`。

自检中的两个例子：

- 护甲是平坦吸收，位置最敏感：`100` 基础、2× 暴击、`50` 护甲，
  暴击在护甲前得 `150`，护甲在暴击前得 `100`，24 种顺序的 spread 为 `50`。
- 只有乘法阶段时，顺序只造成逐步取整误差：基础 `3`、1.5× / 50% / 80% 组合，
  spread 仅 `1`。

## 饱和

- 输入基础伤害夹到 `[0, DMG_MAX]`；
- 每个阶段输出夹到 `[0, DMG_MAX]`；
- 乘除用 128 位中间值，倍率再大也不会回绕；
- 属性（抗性、减伤、暴击率/倍率、护甲）先夹取到合法区间；
- trace 的 `saturated` 与每步的 `saturated` 标记发生截断的位置。

常量与结构体见 `src/damage.c` 顶部，`DMG_MAX` 默认为 `1e9`。
乘除阶段依赖 128 位中间值（GCC/Clang 的 `__int128`），使用 `-std=c11`
默认编译即可；若目标编译器不支持，需要把 `sat_mul_div` 换成溢出检测实现。
