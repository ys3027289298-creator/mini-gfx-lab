# instancing

同一种网格画 100 个实例，每个实例独立变换。实现对同一条软件光栅化管线的两条提交路径：

| 路径 | 提交方式 | 变换来源 |
|---|---|---|
| `uniform` | 每个对象一次绘制调用 | 每次绘制的 uniform 矩阵 |
| `instanced` | 按材质收集实例、合并为一批，每批一次绘制调用 | 用实例索引从实例缓冲取 `gl_InstanceIndex` 对应的 3x4 矩阵 |

实例缓冲支持两种更新方式，并分别计时：

- **每帧重建**：从对象数组重算全部 100 个实例的矩阵。
- **增量更新**：每个实例在批内有固定槽位，只重算本帧发生变化的实例。

100 个对象 / 4 种材质：绘制调用 100 → 4（减少 25 倍），1/4 实例变动时增量更新比重建快约 4 倍。

```bash
make test
```

自检会断言：两条路径的帧缓冲逐像素相同（0 个像素不同）、实例索引错位时能被检出（反证像素比较确实有效）、增量缓冲与全量重建字节一致、增量画面与逐对象绘制一致，并打印绘制调用数和两种更新的耗时。

当前机器（x86_64，gcc 13.3，`-O2`）5 次运行的中位示例：

```
instances=100
materials=4
batches=4
batch_sizes=25,24,25,26
draw_calls_uniform=100
draw_calls_instanced=4
draw_call_reduction=25.00x
pixels_painted=14271
pixels_differing=0
misindex_diff_pixels=712
rebuild_us_per_frame=0.986
incremental_us_per_frame=0.249
incremental_speedup=3.97x
incremental_all_dirty_us_per_frame=0.998
```

5 次重复：重建 0.980–0.996 µs，增量 0.246–0.253 µs，加速比 3.93–4.00x。画面哈希 `bb0813aa` 在 `-O0`、`-O2`、ASan+UBSan 下一致。

衡量口径：

- 绘制调用：一次 `submit_*` 中对某一批/某一对象的提交计 1 次。100 个对象、4 种材质 → 离线路径 100 次，实例化路径 4 次。两路径提交的实例数同为 100。
- 耗时：先预热 200 帧，再对 2000 帧计时；每帧把同一更新连续执行 16 次取整块时间（避免单次 `clock_gettime` 的调用开销淹没 sub-µs 工作量），再除以 16。计时只覆盖实例数据生成，不含光栅化。
- 增量路径的每帧脏实例数为 25（100 个对象中每帧有 1/4 在动），写入量 1600 B vs 重建路径 6400 B。`incremental_all_dirty_us_per_frame` 是全部 100 个实例都变脏时的增量耗时，用于和重建路径对比，两者差别只在收集逻辑。
- 这些是 CPU 侧实例数据生成与提交计数的数字，光栅化耗时未计入；换到真实 GPU 上绘制调用数的下降会保留，但 µs 级数值会完全不同。测试环境为 WSL2，计时受宿主机调度影响，因此报告区间而非单点。
