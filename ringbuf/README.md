# ringbuf

音频线程（消费者）与主线程（生产者）之间的无锁 SPSC 环形缓冲。`make test`
跑全部自检；`make test-sanitizers` 额外跑 TSan 与 ASan/UBsan 构建（WSL2 下
TSan 若报 `unexpected memory mapping`，用 `setarch -R ./ringbuf_tsan`）。

## 设计

- 容量向上取整为 2 的幂，元素粒度按字节（`elem_size`），缓冲 64 字节对齐。
- `head`/`tail` 是单调 64 位计数器，永不回绕；环上位置用 `pos & (cap-1)`
  取模，`fill = head - tail` 不需要模运算。64 位下以音频采样率计，数十万年
  才可能溢出。
- `head` 只由生产者写、`tail` 只由消费者写，二者放在不同缓存行（`_Alignas(64)`）
  避免伪共享；溢出/欠载计数器各自挂在所属线程的缓存行上。
- 跨线程可见性：数据先 memcpy，再 `release` 发布自己的索引；对端 `acquire`
  载入对方索引后才碰数据。无锁、无系统调用，每个操作只有一次 acquire 载入。
- 越界处理不覆盖未读数据：
  - 写不下时只接受 `room` 个，其余拒绝，`overrun_events += 1`、
    `overrun_samples += 拒绝数`；
  - 读不够时只交付已有样本，`underrun_events += 1`、
    `underrun_samples += 缺口数`，目标缓冲中缺口位置保持原样不动；
  - 长度为 0 的调用不计数。
- 文件内同时提供同语义的互斥锁版本 `LockBuf` 作为对照预言机。

## 测试覆盖（全部在 `src/ringbuf.c` 内）

| 测试 | 验证内容 |
|---|---|
| `test_basic` | 容量取整、非法参数、空读欠载计数、满写溢出计数、FIFO 顺序、0 长调用不计数 |
| `test_wraparound` | cap=4 跑 5000 轮随机读写，强制走环尾拆段 memcpy，逐样本核对序号 |
| `test_float_elements` | float 元素位模式原样保留（音频样本场景） |
| `test_fuzz_equivalence` | 20 万步单线程随机操作，无锁版与加锁版的返回值、样本、四个计数器逐次一致 |
| `test_concurrent_equivalence` | 4 线程同调度屏障驱动（三屏障保证先写后读），两种实现每阶段接受/交付量与完整样本流逐样本一致 |
| `test_stress` | 5 组自由运行 SPSC，共约 1.1 亿样本：重溢出/重欠载/混合/2 槽环 256 大块/背压不丢样本；join 后做守恒对账（交付+溢出=生产、gap+尾部拒绝=溢出计数），无重排无重复 |

## 欠载次数与缓冲区大小的关系

模拟音频回调时钟：消费者每 tick 固定要 256 个样本，主线程以概率 `p` 停顿
1..k 个 tick，恢复后一次性补发欠账。同一停顿序列对所有容量重放（10 万 tick）。

重抖动（p=0.03，最长停 4 tick）实测：

| cap | cap/周期 | 欠载事件 | 欠载样本 | 溢出事件 | 溢出样本 |
|---:|---:|---:|---:|---:|---:|
| 64 | 0.25 | 100000 | 20362624 | 81834 | 18819968 |
| 128 | 0.50 | 100000 | 15125248 | 81834 | 13582592 |
| 256 | 1.00 | 18166 | 4650496 | 4893 | 3107840 |
| 512 | 2.00 | 13274 | 3398144 | 3669 | 1855232 |
| 1024 | 4.00 | 7219 | 1848064 | 1190 | 304640 |
| 2048 | 8.00 | 6030 | 1543680 | 0 | 0 |
| 4096 | 16.0 | 6030 | 1543680 | 0 | 0 |
| 8192 | 32.0 | 6030 | 1543680 | 0 | 0 |

规律：容量小于一个回调周期（256）时每个 tick 都欠载；1 个周期是拐点，
欠载事件骤降一个数量级；容量继续增大只能吸收更短的停顿，欠载收敛到
"停顿时长超过缓冲可覆盖 tick 数"的硬下限；到 8 个周期后补发突发也不再
溢出，再加大缓冲不再改善任何指标——工程上 2~4 个周期是甜点区。
