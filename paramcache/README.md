# paramcache

批次渲染的着色参数缓存与批更新：按参数键去重、脏标记只推送变化项、
批次之间复用缓存状态，输出与"每批次重设全部参数"逐像素一致。

## 设计

- 模拟 GPU 后端：uniform 槽位 + 帧缓冲，`backend_set` 计数对应真实
  `glUniform*` 调用次数。
- `ParamCache` 用参数键直接索引（O(1) 查找，天然按 key 去重），保存
  `desired`（逻辑态）/`flushed`（已推送态）/`dirty` 三组状态。
- `cache_set`：同值重复写入直接丢弃；值变化才置脏。
- `cache_flush`：一次线性扫描，只把脏键推给后端，并在推送前再比对一次，
  冗余脏标记也不会产生后端调用。缓存跨批次保留，未变化的参数零调用。
- `cache_audit`：影子审计，逐键比对逻辑态与后端实际状态，漏标脏标记
  导致的不一致必然被检出；软件着色让每个参数都参与像素校验和，漏标
  同时会造成帧缓冲差异（测试中用故障注入验证）。
- 开销与参数种类数线性：`scan_ops == 批次数 × 参数种类数`，设置次数
  与实际变化事件数严格相等。

```bash
make test
```

测试会打印逐批次重设与缓存路径的参数设置次数、下降百分比、去重命中数，
以及 16/64/256/1024 种参数下的线性扩展开销表。
