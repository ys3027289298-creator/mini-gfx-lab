# atten

俯视视角下的实体光照衰减：把**屏幕空间**衰减换成**世界空间距离**衰减。

```bash
make test     # 自检，打印判据与亮度表，并写出 out/ 下的渲染图与剖面数据
make images   # 在 out/ 下合成对比图（六格 + 剖面曲线）
```

## 问题

实体离屏幕中心越远越暗，玩家误以为是雾。实际原因是光照里用的是屏幕空间衰减：
亮度由实体的**视口像素半径**决定。这带来两个后果：

- **跟着相机走。** 平移镜头时，同一个物体亮度会变；缩放时也会变。同一世界点在
  52 m 处，镜头正对时增益 0.206，镜头朝它平移 30 m 后变成 0.784（+281%）。
- **在视口角归零。** 屏幕空间衰减在半径 `R` 处直接截断到 0，所以屏幕边缘像一层
  雾；世界空间衰减则一直按 1/d² 继续衰减。

## 两种模型

| | 公式 | 性质 |
|---|---|---|
| 屏幕空间（原实现） | `A_s(d) = 1 − smoothstep(d / R)` | 依赖视口；`d ≥ R` 恒为 0 |
| 世界空间（修正） | `A_w(d) = 1 / (1 + (d / d0)²)` | 只依赖世界距离；远处 1/d² |

`R` = 半视口对角线长度 = `hypot(W, H) / 2 / px_per_m`。本场景 3840×2160 @ 30 px/m，
`R = 73.43 m`。

### 换算公式的推导

近处必须对得上，所以让两条曲线在相机正下方（`d → 0`）**值和曲率都相等**：

```
A_s ≈ 1 − 3 (d/R)²
A_w ≈ 1 −     (d/d0)²
       →  d0 = R / √3 = 42.39 m
```

这不是随手取的比例。如果按"屏幕半径直接当世界半径"取 `d0 = R`，20 m 内最大偏差
**12.1 %**；取 `d0 = R/2` 则是 **6.1 %**；只有 `d0 = R/√3` 能把误差压到 **0.35 %**。
`make test` 里的 `bad_conversion_rejected` 就是拿这两个错误换算当反例的。

### 两者的解析关系

两条曲线之比有闭式解，记 `t = d/R`：

```
A_s / A_w − 1 = t³ (2 − 9t + 6t²)
```

- `t = 0`：比值 1（相机处对齐）；
- 唯一的另一个根：`t = (9 − √33) / 12 = 0.27129`，即 **交叉点 d = 19.92 m**，
  两边增益都是 **0.819142**；
- 交叉点之后 `A_s < A_w`，屏幕空间更暗；`d = 30.46 m` 处偏差到 **−5 %**；
- `d ≥ R` 时 `A_s ≡ 0`，而 `A_w` 仍在 0.23 附近按 1/d² 继续衰减。

近场判据（`d ≤ 20 m`，即交叉点所在窗口）最大相对偏差 **0.352 %**，远低于 5 %。

## 自检

`make test` 的判据（任一失败返回非零）：

| 名称 | 内容 |
|---|---|
| `gain_at_camera` | 两者在 d = 0 都为 1 |
| `near_field_<=5%` | 0..20 m 最大相对偏差 ≤ 5 %（实测 0.352 %） |
| `single_crossing` | 交叉点唯一且等于解析值 `(9−√33)/12 · R` |
| `diverge_past_near` | 5 % 偏差出现在近场窗口之外、视口角之内 |
| `world_inverse_square` | 远处 `A(80 d0)/A(40 d0) = 0.2501` |
| `screen_dies_at_corner` | 屏幕模型在 R 处为 0，世界模型仍有 0.23 |
| `screen_is_view_dependent` | 同一物体 52 m：正视 0.206，平移后 0.784 |
| `screen_is_zoom_dependent` | 同一物体 32 m：缩放 -1 档 0.878，+1 档 0.045 |
| `bad_conversion_rejected` | 错误换算 d0=R / d0=R/2 都会被 5 % 判据拒绝 |
