# mini-navgrid

8 方向 A*、对角禁止切角、视线可达平滑、增量重规划实验平台。

```bash
make test
```

## 区域划分（`src/regions.c`）

开放世界的批量剔除与流式加载需要知道“哪些格子属于同一块”。`regions` 模块把
可走格子按 **4 连通 + 渲染区块边界** 划分为区域：

- **连通性**：4 邻接。本库 A* 的对角步要求两侧正交格都可走，因此对角可达的格子
  一定 4 连通；按 4 连通划分得到的正好是禁止切角规则下的可达集合。
- **区块对齐**：区域不跨越渲染区块边。区域完全属于一个区块，所以“区块加载
  ⇒ 其全部区域加载”，每个区域可作为一个剔除/绘制批次。
- **规范 id**：`id = 区域内最小线性格号 + 1`，`0` 表示阻挡/无区域。同一划分
  永远产生同一份 label 数组，增量结果可直接与全量划分逐格比对。
- **增量重标**：`rg_toggle()` 只重标与改动格相关的区域——封路最多把所在区块的
  一个区域拆成 4 块，开路最多合并 4 个相邻区域；其他区块与同区块其他区域的
  标签原样保留。

API 见 `src/regions.h`：`rg_init / rg_build / rg_toggle / rg_region_at /
rg_chunk_regions / rg_stats / rg_validate`。

结论：区块越小，区域越碎、批次越多，但每批更小、剔除粒度更细；迷宫这类细长
地形对区块尺寸最敏感（128 区块时每区块最多 57 个区域）。开放地形下区域数
≈ 区块数，区块尺寸可直接按目标批次上限选。

### 实测性能（本机 GCC 13 `-O2`）

- 全量构建 102400 格：各区块尺寸下最好 ~0.75 ms，中位数 ~0.8 ms（预算 20 ms）。
- 单格 `rg_toggle`：中位数 0.001–0.04 ms，p99 ≤ 0.08 ms；代价与受影响区域大小
  成正比（最坏情形为 64 格区块里 3635 格的整块区域翻转）。
