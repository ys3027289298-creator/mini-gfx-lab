# mini-navgrid

8 方向 A*、对角禁止切角、视线可达平滑，以及地图改动后的拓扑检查。

```bash
make test      # 自检 + 十万格性能测试
make bench     # 极端地图耗时（400x250 = 100k 格）
```

`make bench` 不是 `make test` 的依赖，可单独运行。

## 拓扑检查

`topo_check(grid, spawn, &report)`：

- `components`：可走区域的连通分量数。
- `cut` / `cut_regions` / `cut_cells`：可达区域之外被切断的每个区域，
  含大小、包围盒、代表格，按大小降序。
- `patch` / `patch_cells`：建议打开的阻挡格（补哪几格）。
- `repair_ok`：把这些格子打开后整图是否连通。

`spawn` 给一个可走格时，它所在分量是"可达区域"，其余全算被切断；
传 `{-1,-1}` 则以最大分量为可达区域。

### 正确性依据

禁止切角时，斜向一步合法当且仅当两个正交相邻格都可走，因此任意合法的
斜边都隐含一条正交路径，**可达性等价于 4 连通**。所以连通分量用 4 邻域
BFS 计算；自检里另建一张按真实 `step_ok()` 连边的并查集，逐格比对分区。
`random_dsu_match`、`checker_dsu_match` 等断言覆盖随机破坏、棋盘格等情形。

### 修复建议是否最小

对阻挡格做多源 BFS，得到每格最近的分量及"要开几格才能到它"；相邻两个
来源不同的阻挡格构成候选桥。再在分量图上做 MST，把选中的格子链写入
`patch`。**两个分量时这是精确最小割**，自检中 `split_brute_min` 等用例
用暴力枚举验证补格数与最优值相等。三个及以上分量属于 Steiner 树问题，
MST 只是上界，`repair_ok` 只保证能连通，不宣称全局最优。

### 复杂度与实测

单次检查是 O(格子数 + 候选桥数·log)，全部按行优先线性扫描，十萬格
（400x250）在常规地图上约 1–2 ms；最坏情况（六成以上密度、五万个分量）
约 8–16 ms，均低于 50 ms 要求。
