# animcomp

动画数据三段压缩流水线：关键帧抽稀 → 曲线拟合 → 求值缓存。

## 三段处理

1. **关键帧抽稀（decimate）**：对均匀采样的原始轨道做 RDP 抽稀，保留线性插值误差
   不超过 `EPS_DEC` 的最少关键帧。
2. **曲线拟合（fit）**：逐段选择形状 + 贪心删键。Catmull-Rom 样条穿过同一组键
   并不等于分段线性——急转弯处样条会把拐角磨圆、偏差可超阈值——所以每个段独立
   选择：样条偏差 ≤ `EPS_FIT` 就用样条，否则回退线性（1 bit/段记录形状）。
   删键仅当被影响的所有段（CR 支撑半径 ±2 段）删后仍有合法形状时才接受。
   两段阈值可叠加：总误差 ≤ `EPS_DEC + EPS_FIT`（三角不等式），程序在 8 倍
   过采样网格上**实测**各段误差与该上界对照。
3. **求值缓存（cache）**：按 1/240 s 量化时间的直接映射缓存。命中时返回的是
   直接求值存下的同一份比特，测试用 `memcmp` 验证命中值与直接求值逐位一致。

## 构建与自测

```sh
make test
```

输出：各段误差实测值 vs 阈值、缓存命中一致性与命中率、以及数据体积 /
求值耗时与原始数据的对照表（原始 = 均匀采样 4 B/样本；压缩后 = 8 B/关键帧
+ 1 bit/段）。求值耗时是权衡而非纯收益：压缩轨道用二分查找 + 样条求值，
比原始数组直接索引慢，缓存命中把单次求值拉回同一量级。
