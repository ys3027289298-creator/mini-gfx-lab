# rollback

联机单位瞬移/回退的修复：客户端预测 + 服务器权威点回滚重放。

```bash
make test     # 自检（含 6480 组种子×链路条件的性质扫描）
make metrics  # 生成 metrics.csv 与收敛曲线 metrics.svg
```

## 问题

客户端按键后等服务器确认才移动 → 输入延迟；或者收到服务器状态就直接覆盖 →
单位在“预测位置”和“服务器位置”之间来回跳（回退/瞬移）。

## 做法

1. 本地立即按输入推进（零感知输入延迟）。
2. 每个 tick 记下 `(tick → 输入, 状态)`。
3. 收到快照 `(tick = a, 位置)`：
   - 若 `a` 与本地预测一致 → 只是 ack，不重放；
   - 否则把状态恢复为 `a` 的权威位置，用**同样的 `unit_step`** 重放 `(a, 当前 tick]`
     的所有未确认输入，然后继续预测。
4. 统计：回滚次数、重放 tick 数、最大回滚深度、快照 ack/stale/dropped。

**回滚重放 == 直接按权威序列推进**：`rb_apply()` 每次回滚都会独立地从快照状态重放
一遍权威输入序列并逐 float 比对；测试再从外部用主机自己的输入轨迹逐 tick 比对
（`verify_replay`）。任何不一致都会使 `replay_mismatch` 非零并让自检失败。

## 三种客户端

同一输入流、同一条丢包/抖动/重复链路：

| 模式 | 行为 | 结果 |
|---|---|---|
| `rollback` | 预测 + 确认点回滚重放 | 误差在回滚当 tick 归零，预测误差收敛 |
| `ignore` | 只预测、从不校正 | 误差按每次不可预测事件累加，永不收敛 |
| `snap` | 收到哪个快照就画哪个 | 随乱序包前进/后退，即“瞬移回退” |

## 结果

`metrics.svg` 上图为整场对局误差曲线（回滚/ignore/snap 三条），下图为第一次击退的
逐 tick 放大。示例配置（20 Hz、单向 100 ms ±60 ms、3% 丢包、5% 重复、5 次不可预测
击退）下：

- 回滚 5 次，全部 bit-exact（`mismatch 0`），最大回滚深度 3 tick；
- 每次击退后误差在 3 tick（0.15 s）内回到 0；
- `ignore` 客户端误差累计到 3.0；`snap` 客户端反复回退且平均滞后约 0.5 单位。
