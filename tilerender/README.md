# tilerender

`make test` 跑自检。一条渲染链，三段各自独立可测：

1. **拼接**：地图切成 8×8 的边缘块，每块的变体是一张 64×64 拼好的图——块内每格用它自己的 4 邻接掩码着色，块边上的格看相邻块的格子，所以跨块接缝也接得上。内容键 = 占用位图 + 边外占用位 + 每格图块 id。
2. **缓存**：变体按内容键寻址，同键必然同图，所以条目不会"过期"，只会在最后一个引用它的块改走之后失效。改一格只重拼它所在的块，以及块边界上确实被这一格影响的邻块；内容没变就是空操作。
3. **排序**：块内相邻同图块合并成横条，每条带统一深度键（层 → y → x），整张表一次 `qsort` 再光栅化。图层是 alpha 混合的，所以顺序真的会影响像素。

自检逐帧与"逐图块直接绘制"的参考实现做逐像素比较，并打印
`rebuild / query / hit / miss / gen / inval / live / cmds / tiles`。
命中率在重复地形上单独报（96 块只生成 9 个变体，命中率 0.9062），
绘制调用数报 `cmds` 与 `tiles` 及两者比值。改动一格的重建块数单独断言：
块内 = 1、跨块边 = 2、跨块角 = 3 且对角块不动；把改动改回去应当是缓存命中、
不重新生成变体。

把排好序的绘制表倒着画一遍会与参考实现不一致（`reverse_differs`），
说明深度排序确实起作用，而不是碰巧像素一样。
